# 视觉 → 电控 串口协议（v2，28 字节）

> 视觉侧：LicheeRV Nano（SG2002）。状态：**已实现**——帧组装与 CRC 在 `src/uart_frame.h` / `src/uart_frame.cpp`
> （纯函数，只依赖 `<stdint.h>`），由 `src/uart_out.cpp` 的串口线程调用；开关是 `config.yaml` 的
> `uart_format`（`ascii` | `binary`；**出厂 `config.yaml` 已设为 `binary`**，配置里缺这个键时代码按 `ascii` 兜底）。
>
> ⚠️ **二进制路径已按本文档实现，并在 Linux 上用 pty 端到端验过真实字节，但还没上板实机联调**——`uart_format` 一改，线上字节就
> 从 v1 变成本文档的 28 字节帧。需要 ASCII 抓包调试时把它改回 `ascii`（[UART_PROTOCOL.md](UART_PROTOCOL.md)），
> 本文档是目标协议。实现细节与**验证范围**（哪些验过、哪些没验）见 §8。

## 1. 物理层

| 项 | 值 |
|---|---|
| 接口 | UART，3.3V TTL，共地，TX/RX 交叉 |
| 格式 | 115200 8N1，无流控 |
| 视觉侧设备 | `/dev/ttyS1`（待对排针确认） |
| 发送节奏 | **固定 50Hz，有没有目标都发**（心跳） |

## 2. 帧格式（小端）

```
A5 5A | LEN | SEQ | CMD | 数据(21 字节) | CRC16
```

| 字段 | 值/说明 |
|---|---|
| `LEN` | 固定 `0x15`（21） |
| `SEQ` | 每发一帧 +1，0..255 回绕（**只用于丢包统计**，不参与控制） |
| `CMD` | `0x01` 控制帧 |
| `CRC16` | CCITT-FALSE：poly `0x1021`，init `0xFFFF`，不反射；小端；覆盖 `LEN` 到数据末尾（offset 2 ~ 4+LEN） |
| 帧总长 | **28 字节** |

## 3. 数据（21 字节）

| 偏移 | 类型 | 字段 | 单位 | 说明 |
|---|---|---|---|---|
| 0 | u8 | `detected` | — | 1 = 有目标；0 = 无 |
| 1 | f32 | `yaw` | 度 | 正 = 目标在光轴右侧（**瞄准点** = 引导灯上方装甲板中心） |
| 5 | f32 | `pitch` | 度 | 正 = 目标在光轴上方（**瞄准点** = 引导灯上方装甲板中心） |
| 9 | f32 | `vyaw` | 度/秒 | 角速度（前馈用） |
| 13 | f32 | `vpitch` | 度/秒 | 角速度（前馈用） |
| 17 | f32 | `dist` | 米 | 斜距；**`-1.0` = 无效** |

## 4. 使用规则

- `detected == 1`：角度可用。
- `detected == 0`：角度全为 0、`dist = -1.0`，**不要使用**。
- `detected == 0` 持续 **<80ms**：建议沿用上一帧角度（避免抖动）；**>200ms**：停止闭环/回中。
- 单帧 CRC 错：丢弃该帧，**不要重置角度状态**；`>300ms` 收不到帧：视为视觉掉线，停机。
- 角度范围约水平 ±32°、垂直 ±18°。

### 发送频率怎么选（检测 80Hz ≠ 发送 80Hz）

串口发的是**最新结果**，不是"每帧检测结果"，所以发送频率与检测频率无关；超过 80Hz 不会产生新数据。

| 发送频率 | 每个结果发几次 | 重复帧 | 最坏「结果出来 → 发出」延迟 | 带宽(115200) |
|---|---|---|---|---|
| **50Hz（默认）** | 62.5% 的结果各发 1 次 | 0 | ≈25ms | 12% |
| 80Hz | 每个结果正好 1 次 | 0 | ≈18ms | 19% |
| 100Hz（可选） | 125%（每 5 个结果有 1 个发 2 次） | 20% | ≈15ms | 24% |

- 想省带宽：50Hz 够用；想压低最坏延迟：80Hz（零重复）或 100Hz（更小延迟、多 20% 重复帧）；
- `SEQ` 在重复帧上**不变**，电控若不想重复处理，可用 `SEQ` 去重。

## 5. 示例（可直接当解析测试用例）

```text
A5 5A 15 07 01 01 A4 70 45 41 A4 70 B5 40 CD CC 34 42 CD CC 44 C1 1B 2F 5D 40 42 8E
→ SEQ=7 CRC=0x8E42 detected=1 yaw=12.34 pitch=5.67 vyaw=45.20 vpitch=-12.30 dist=3.456
```

```text
A5 5A 15 08 01 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 80 BF 99 7C
→ SEQ=8 CRC=0x7C99 detected=0 角度全 0 dist=-1.0（无目标心跳帧）
```

## 6. CRC16 参考代码（C）

```c
static uint16_t crc16(const uint8_t *p, uint32_t n) {
  uint16_t c = 0xFFFF;
  for (uint32_t i = 0; i < n; ++i) {
    c ^= (uint16_t)p[i] << 8;
    for (int b = 0; b < 8; ++b)
      c = (c & 0x8000) ? (uint16_t)((c << 1) ^ 0x1021) : (uint16_t)(c << 1);
  }
  return c;
}
/* 校验：crc16(buf+2, 3 + buf[2]) 与 buf[5+buf[2]] | buf[6+buf[2]]<<8 比较 */
```

## 9. 怎么在串口助手里看懂这些字节

串口助手显示的 `A5 5A 15 85 01 00 ...` 是**十六进制字节**，一段里往往粘着好几帧，判断方法：

| 想确认的事 | 怎么看 |
|---|---|
| 一段里有几帧 | 字节数 ÷ 28（整除才对）。`RECV HEX/112` = 4 帧，`/84` = 3 帧 |
| 一帧从哪开始 | 找 `A5 5A`（帧头）。它在数据里不会乱出现，因为后面必须跟 `15 01` 且 CRC 对得上 |
| 是不是新帧 | 第 4 个字节是 `SEQ`，每帧 +1（0..255 回绕）。`73 74 75 76` = 115→118 |
| 有没有坏帧 | 最后 2 字节是 CRC（小端）。坏帧直接丢，**不要重置角度状态** |
| 有没有目标 | 数据区第 1 个字节 `detected`：`01` 有、`00` 无。`00` 时角度全 0、`dist` 是 `00 00 80 BF`（= -1.0f） |
| 一次弹 3~4 帧正常吗 | 正常。串口助手按「这一瞬间读到多少字节」成块显示，50Hz 下 80ms 正好 4 帧 |

**不想手算就用脚本**（仓库内，纯标准库，Windows/板端都能跑）：

```sh
python tools/decode_v2.py --file 抓包.txt        # 串口助手整段输出存成 txt，带时间戳也没关系
type 抓包.txt | python tools/decode_v2.py -      # 或者用管道
python tools/decode_v2.py --hex "A5 5A 15 85 01 00 ... 08 EF"
```

它会打印每帧的 `SEQ`、`CRC(线上/重算)`、`detected/yaw/pitch/vyaw/vpitch/dist`，并在结尾给出
「全心跳 / 有坏帧 / SEQ 断档」的结论。2026-11-11 实测：板端抓到的 11 帧全部 CRC 正确、全为心跳帧。

**给电控现成的解析代码**：[uart_v2_parser_example.c](uart_v2_parser_example.c) —— 单文件、零依赖，
`v2_parser_feed()` 逐字节喂数据，内部自动找帧头 / 校验 CRC / 坏帧丢弃 / 重新同步，附命令行自检。
2026-11-11 用真实抓包实测：干净输入 32 帧 0 错；把带时间戳和 `RECV HEX` 日志的原始文本直接喂进去，
同样解出 32 帧、0 CRC 错，并自动丢掉 80 字节日志噪音。

### 9.1 联调验收工具（`tools/uart_accept.py`）

联调时用 **USB-TTL 并线监听视觉板 TX**（TTL 的 RX 接视觉 TX，双方共地），终端里跑：

```sh
python tools/uart_accept.py --port COM7 --seconds 30 --label 靶子1米
```

它实时打印每一帧（`SEQ / detected / yaw / pitch / vyaw / vpitch / dist / 瞬时帧率`），
30 秒后给一张验收表：

| 判定项 | 通过条件 |
|---|---|
| 帧率 | 50 Hz ±20%（`--expect-rate` 可改） |
| CRC 错误 | 0 |
| 长度错误 | 0 |
| 最长断流 | < 300 ms（协议掉线判据） |
| SEQ 丢帧 | ≤ 1%（≤5% 告警） |
| 字段合法 | `detected` 只能是 0/1、五个 float 必须有限 |
| 数值范围 | \|yaw\|≤32°、\|pitch\|≤18°、dist ∈ [-1, 30] |
| 心跳比例 | 只做 INFO（无目标时 100% 属正常） |

退出码：`0` 通过、`1` 有失败项、`2` 串口/参数错误 —— 可直接用在脚本里。
另有 `--file 抓包.txt`（回放文本/二进制抓包）、`--selftest`（自检判定逻辑，不需硬件）。

**电控侧的终端对照**：装 `dart_mcu_uart/test/v2_acceptance_print.c`（见该目录 README §7），
电控固件每秒打印 `[v2] rx=.. crc=.. seq=.. age=..` 和 `[v2] det=1 yaw=.. dist=..`，
两边对同一帧的 `SEQ`、`yaw`、`dist` 应当完全一致 —— 这就是联调时最直接的"你说的和我收到的对得上"。

### 9.2 视觉侧接收电控帧并打印（`uart_rx_print`）

跑 licheeRV 程序时，它**同时**接收电控发来的 `CMD=0x02`（33 字节）帧，并把内容打到终端：

```
[MCU] 收到电控数据（CMD=0x02，33 字节帧），下面按 10Hz 打印
[MCU] seq=  7 state=FLIGHT flags=0x07(imu=1 bias=1 acc=1) roll=   1.00 pitch=  -2.00 yaw=    3.50 | gx=   4.00 gy=  -5.25 gz=   6.75 | age=0ms
```

| 项 | 说明 |
|---|---|
| 配置 | `config.yaml`：`uart_rx_print: true`（默认开）、`uart_rx_print_hz: 10`（打印限频 1~100，电控 100Hz 全打会刷屏） |
| 只打印不处理 | 解析结果只存快照 + 打印，**不参与任何角度/控制计算** |
| 终端可见性 | `start.sh` 会把 camera 的 stdout 重定向到日志；程序另外开 `/dev/tty` 打一份，所以**手动跑时终端里直接能看到** |
| 开机自启时 | 没有终端，只有日志：`tail -f /tmp/fly_licheerv_capture.log \| grep --line-buffered MCU` |
| 诊断 | 每 5 秒的 `UART sent=...` 行尾部带 `rx_frames= rx_crc= rx_other= rx_age=ms`；`rx_age=-1` 表示还没收到过电控帧 |
| 坏帧 | CRC 错/长度错计入 `rx_crc`，且**不覆盖**上一帧数据；回环收到自己的 `0x01` 帧计入 `rx_other` |
